# 动量轮倒立摆（Reaction Wheel Inverted Pendulum）IsaacLab 仿真技术方案

> **目标**: 在 IsaacLab 框架下，完成动量轮倒立摆的物理仿真、控制器设计与训练部署全流程。
> **适用范围**: Isaac Sim 4.x / IsaacLab 1.x，Python 3.10+，支持 GPU 并行化 RL 训练。

---

## 一、物理系统建模

### 1.1 系统描述

动量轮倒立摆由以下部件组成：

```
         ┌──────────────┐
         │   飞轮 (m_w)   │  ← 电机驱动，高速旋转
         │   I_w, φ(t)   │
         ├──────────────┤
         │              │
         │   摆杆 (m_p)   │  ← 绕底部转轴自由摆动
         │   I_p, L      │
         │              │
         └──────┬───────┘
              [●] 转轴 (无驱动，被动)
             ///////  地面
```

- **摆杆**: 底部通过被动转动关节连接基座，可在竖直平面内自由摆动（1 DOF）
- **飞轮（动量轮）**: 安装在摆杆顶端，由电机驱动高速旋转（1 DOF）
- **总自由度 = 2**: 摆角 θ（相对竖直方向）、飞轮转角 φ（相对摆杆）

### 1.2 动力学方程（拉格朗日推导）

**广义坐标**: `q = [θ, φ]^T`，其中 θ 是摆杆角度，φ 是飞轮相对摆杆的角度。

**系统参数定义**:

| 符号 | 含义 | 单位 |
|------|------|------|
| m_p | 摆杆质量 | kg |
| m_w | 飞轮质量 | kg |
| l_p | 摆杆质心到转轴距离 | m |
| L   | 摆杆总长度 | m |
| I_p | 摆杆绕质心转动惯量 | kg·m² |
| I_w | 飞轮绕转轴转动惯量 | kg·m² |
| g   | 重力加速度 (9.81) | m/s² |
| τ_m | 电机输出扭矩 | N·m |
| b_p | 摆杆转轴粘性摩擦 | N·m·s/rad |
| b_w | 飞轮转轴粘性摩擦 | N·m·s/rad |

**完整动力学方程**:

设 `I_total = I_p + m_p*l_p² + m_w*L² + I_w`，则：

```
I_total · θ̈ + I_w · φ̈ - (m_p·l_p + m_w·L) · g · sin(θ) + b_p · θ̇ = 0
I_w · (θ̈ + φ̈) + b_w · φ̇ = τ_m
```

**关键物理直觉**: 电机对飞轮施加扭矩 τ_m，飞轮的反作用扭矩驱动摆杆。当摆杆偏离竖直位置时，通过加速/减速飞轮产生反作用力来纠正摆杆姿态。

### 1.3 线性化模型（用于经典控制器设计）

在 θ ≈ 0（接近直立）附近线性化：

```
I_total · θ̈ + I_w · φ̈ - (m_p·l_p + m_w·L) · g · θ + b_p · θ̇ = 0
I_w · (θ̈ + φ̈) + b_w · φ̇ = τ_m
```

状态空间形式 `ẋ = Ax + Bu`（其中 `x = [θ, θ̇, φ̇]^T`, `u = τ_m`）：

```
A = [  0           1              0      ]
    [  (m·g·l)/I_eq   -b_p/I_eq     b_w/I_eq  ]
    [  -(m·g·l)/I_eq    b_p/I_eq    -(I_total·b_w)/(I_eq·I_w) ]

B = [  0                    ]
    [  -1/I_eq              ]
    [  I_total/(I_eq·I_w)   ]
```

其中 `m·l = m_p·l_p + m_w·L`，`I_eq = I_total - I_w`。

## 二、USD/URDF 机器人资产设计

### 2.1 资产结构

使用 URDF 格式定义（IsaacLab 原生支持 URDF 导入并自动转换为 USD）：

```
reaction_wheel_pendulum.urdf
├── base_link (固定基座)
│   └── joint: pivot_joint (revolute, axis=[0,1,0])
│       └── pendulum_link (摆杆)
│           ├── visual: 杆状几何体
│           ├── collision: 简化碰撞体
│           └── joint: wheel_joint (revolute, axis=[0,1,0], 有驱动)
│               └── flywheel_link (飞轮)
│                   ├── visual: 圆盘几何体
│                   └── collision: 简化碰撞体
```

### 2.2 推荐物理参数（参考设计）

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| m_p | 0.1 kg | 轻质摆杆 |
| m_w | 0.3 kg | 较重飞轮，提供更大转动惯量 |
| L   | 0.5 m | 摆杆长度 |
| l_p | 0.25 m | 摆杆质心在中心 |
| I_w | 0.001 kg·m² | 飞轮转动惯量（圆盘 I=½mr²） |
| b_p | 0.001 | 摆杆转轴小摩擦 |
| b_w | 0.0001 | 飞轮转轴极小摩擦 |

### 2.3 关键注意事项

1. **飞轮转动惯量 I_w 至关重要**: 它决定了飞轮能提供的最大反作用扭矩。如果 I_w 太小，系统将不可控（需要极高转速才能产生足够反作用力）。建议飞轮半径至少 5cm，质量至少 200g。

2. **碰撞体简化**: 飞轮用圆柱体近似，摆杆用 box 近似。不需要复杂 mesh。

3. **关节限位**: 飞轮关节设置为 continuous（无角度限位），摆杆关节也设为 continuous（允许 360° 旋转，用于 swing-up 任务）。

4. **驱动模式**: 飞轮关节使用 `effort` 控制（直接控制扭矩），这是最接近真实电机控制的方式。也可使用 `velocity` 控制来模拟速度伺服电机。

## 三、IsaacLab 环境架构

### 3.1 整体架构

采用 **Manager-Based RL Environment** 模式（IsaacLab 推荐的标准范式）：

```
┌─────────────────────────────────────────────┐
│              Task: RWIPBalance              │
├─────────────────────────────────────────────┤
│  ┌───────────────────────────────────────┐  │
│  │         Observation Manager           │  │
│  │  - JointPositionSensor                │  │
│  │  - JointVelocitySensor                │  │
│  │  - BodyOrientationSensor (摆杆姿态)    │  │
│  │  - MotorTorqueSensor                  │  │
│  └───────────────────────────────────────┘  │
│  ┌───────────────────────────────────────┐  │
│  │          Action Manager               │  │
│  │  - JointEffortAction (飞轮扭矩)        │  │
│  │    range: [-τ_max, +τ_max]            │  │
│  └───────────────────────────────────────┘  │
│  ┌───────────────────────────────────────┐  │
│  │         Reward Manager                │  │
│  │  - UprightReward (基于摆杆角度)        │  │
│  │  - TorquePenalty (惩罚大扭矩)          │  │
│  │  - VelocityPenalty (惩罚过高飞轮转速)   │  │
│  │  - SurvivalReward (存活奖励)           │  │
│  └───────────────────────────────────────┘  │
│  ┌───────────────────────────────────────┐  │
│  │      Termination Manager              │  │
│  │  - 摆杆倾角 |θ| > θ_max (如 60°)       │  │
│  │  - 飞轮转速 |φ̇| > ω_max               │  │
│  │  - Episode 时间超时                    │  │
│  └───────────────────────────────────────┘  │
│  ┌───────────────────────────────────────┐  │
│  │    Curriculum / Domain Randomization  │  │
│  │  - 初始角度逐步增大                    │  │
│  │  - 物理参数噪声 (质量、惯量、摩擦)      │  │
│  │  - 传感器噪声                          │  │
│  └───────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

### 3.2 观测空间设计

| 观测量 | 维度 | 范围 | 说明 |
|--------|------|------|------|
| sin(θ) | 1 | [-1, 1] | 摆杆角度正弦 |
| cos(θ) | 1 | [-1, 1] | 摆杆角度余弦 |
| θ̇ | 1 | 不限 | 摆杆角速度 |
| φ̇ | 1 | 不限 | 飞轮角速度（相对摆杆） |
| τ_last | 1 | [-1, 1] | 上一时刻的电机扭矩（归一化） |

**总计观测维度**: 5（最小方案），可根据需要扩展到 7~10 维（增加 sin/cos 的摆杆全局姿态等）。

> **设计理由**: 使用 sin/cos 而非直接角度，可以避免角度周期性带来的学习困难。

### 3.3 动作空间设计

| 动作量 | 维度 | 范围 | 说明 |
|--------|------|------|------|
| τ_cmd | 1 | [-1, 1] | 归一化扭矩指令 → 映射到 [-τ_max, τ_max] |

- τ_max 推荐值: 0.5 N·m（小型电机可达范围）
- 单维连续动作空间，适合 PPO/SAC 等算法

### 3.4 奖励函数设计

**核心思想**: 奖励摆杆保持直立，同时惩罚过度使用飞轮（能量效率）。

```
R_total = w1 · R_upright + w2 · R_torque + w3 · R_velocity + w4 · R_survival
```

| 奖励项 | 公式 | 权重 | 说明 |
|--------|------|------|------|
| R_upright | exp(-α·\|θ\|²) | w1=5.0 | 摆杆越直立，奖励越高 |
| R_torque | -\|τ/τ_max\|² | w2=0.1 | 惩罚大扭矩（节能） |
| R_velocity | -\|φ̇/ω_norm\|² | w3=0.05 | 惩罚过高飞轮转速 |
| R_survival | +1.0 per step | w4=0.5 | 存活即奖励 |

### 3.5 终止条件

| 条件 | 阈值 | 说明 |
|------|------|------|
| 摆杆跌倒 | \|θ\| > π/3 (60°) | 摆杆偏离竖直过多 |
| 飞轮超速 | \|φ̇\| > 500 rad/s | 飞轮转速超过物理/安全限制 |
| 超时 | episode_length > 1000 steps (20s) | 达到最大步数 |

## 四、控制策略设计

### 4.1 方案对比

| 方案 | 适用场景 | 难度 | 性能 | 泛化性 |
|------|----------|------|------|--------|
| **RL (PPO)** | Swing-up + Balance | 中 | 优秀 | 优秀 |
| **LQR** | 仅近直立平衡 | 低 | 良好 | 差 |
| **能量整形 + LQR** | Swing-up + Balance | 高 | 良好 | 中 |
| **MPC** | 全部 | 高 | 优秀 | 中 |

### 4.2 推荐方案: RL（PPO）+ 课程学习

**推荐理由**:
1. IsaacLab 内置完整的 PPO 训练管线
2. 不需要精确动力学模型（对参数误差鲁棒）
3. 课程学习可以统一解决 swing-up 和 balance 两个阶段
4. GPU 并行训练效率极高（4096+ 并行环境）

### 4.3 课程学习策略

```
阶段 1 (Ep 0~500):   初始角度 [-5°, +5°]    → 学会在近直立状态保持平衡
阶段 2 (Ep 500~1500): 初始角度 [-30°, +30°]  → 学会从小扰动中恢复
阶段 3 (Ep 1500~3000): 初始角度 [-90°, +90°] → 学会从大角度 swing-up
阶段 4 (Ep 3000~5000): 初始角度 [-180°, +180°] → 学会从任意初始位置 swing-up
```

### 4.4 备选方案: 经典控制（如果 RL 训练效果不好）

1. **能量整形 (Energy Shaping)**: 控制摆杆的机械能，使其达到与直立位置对应的能量水平
2. **切换控制**: 当摆杆能量达到目标值后，切换到 LQR 进行精细平衡
3. **LQR 参数**: 在 θ=0 处线性化，用 MATLAB/Python control 工具箱求解 K 矩阵

## 六、实施步骤

### Phase 1: 资产创建 (预计 1-2 天)

1. 使用 SolidWorks/Blender 或直接手写 URDF 创建机器人模型
2. 在 Isaac Sim 中加载 URDF，验证可视化正确
3. 调整质量、惯量参数使其物理上合理
4. 手动测试关节运动和碰撞检测

### Phase 2: 基础环境搭建 (预计 2-3 天)

1. 在 IsaacLab 中注册自定义 Robot 类
2. 实现 `ReactionWheelPendulumEnv` 继承 `ManagerBasedRLEnv`
3. 配置 ObservationManager、ActionManager
4. 实现基本的 Reward 和 Termination 逻辑
5. 单环境测试：手动发送扭矩指令，观察物理行为

### Phase 3: 控制器验证 (预计 2-3 天)

1. 实现 LQR 平衡控制器作为 baseline
2. 在仿真中测试 LQR 能否稳定近直立状态
3. 验证物理参数是否合理（飞轮能否提供足够的反作用扭矩）

### Phase 4: RL 训练 (预计 3-5 天)

1. 配置 PPO 训练 pipeline
2. 先在小规模（128 env）进行调试训练
3. 扩展到 4096 env 全规模训练
4. 监控训练曲线，调整奖励权重和超参数
5. 实施课程学习

### Phase 5: 评估与可视化 (预计 1-2 天)

1. 在测试环境中评估最终策略
2. 录制仿真视频（swing-up + 平衡全过程）
3. 分析飞轮转速、扭矩的时间曲线
4. 对比 RL vs LQR 的性能指标

## 七、潜在风险与对策

| 风险 | 概率 | 影响 | 对策 |
|------|------|------|------|
| 飞轮 I_w 不足导致不可控 | 中 | 高 | 增大飞轮半径/质量；在 URDF 中调整惯性参数 |
| RL 训练不收敛 | 低 | 中 | 先验使用 LQR baseline 辅助；调整奖励权重；降低任务难度 |
| IsaacLab API 版本不兼容 | 中 | 中 | 锁定 IsaacLab 版本；查阅最新文档 |
| GPU 显存不足 (4096 env) | 低 | 中 | 降低并行环境数；使用更小网络 |
| 飞轮转速发散 | 中 | 低 | 增加速度惩罚权重；添加飞轮转速 hard limit |
| Sim-to-Real 差距 | - | - | 本项目为纯仿真，暂不考虑 |
